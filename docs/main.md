# CLI 세부 설계 (`main.c`, 최무헌)

> **기준 문서:** [모듈 구성과 호출 계약](architecture.md), [파서 세부 설계](parser.md).
> SQL 파일을 읽고 명령을 실행하는 흐름, 출력과 종료 정리를 다뤄요. 구현 전 설계이며 실제 실행 결과는 아니에요.

## 1. 맡는 것과 맡지 않는 것

| 맡는 것 | 맡지 않는 것 (담당) |
| --- | --- |
| 실행 인자 확인, SQL 파일 전체 읽기 | 문장 분리, SQL 문법 해석 (`parser.c`) |
| 파서와 실행기 호출, 문장 번호 관리 | 테이블, 값, WHERE 검증 (`execute.c`) |
| 저장소 열기와 닫기 요청 | 자동 ID, 바이너리 파일 처리 (`storage.c`) |
| 행과 성공 결과 출력, 오류 출력, 종료 코드 결정 | 트랜잭션, 실패 명령 자동 재시도 |

## 2. 입력과 실행 정책

- 호출 형태는 `프로그램 SQL파일경로`예요. SQL 경로 인자를 정확히 하나 받아요.
- 저장 대상은 현재 작업 디렉터리의 `users.sans` 하나예요. SQL의 테이블명으로 파일 경로를 만들지 않아요.
- 상위 디렉터리는 만들지 않아요. 현재 작업 디렉터리에 쓸 수 없으면 `storage_open()` 오류로 처리해요.
- 명령 하나를 파싱한 뒤 바로 실행해요. 파일 전체를 먼저 검증하거나 명령 배열을 만들지 않아요.
- 처음 발생한 오류에서 중단해요. 앞서 성공한 INSERT와 이미 출력한 SELECT 행은 되돌리지 않아요.
- 빈 파일, 공백이나 빈 문장만 있는 파일은 `DB_END`로 끝나는 성공이에요. 아래 순서에서는 저장소를 먼저 열기 때문에 파일 생성 여부는 `storage_open()` 정책을 따라요.

## 3. 함수와 자원

### 3.1 내부 함수

아래 보조 함수는 `main.c`의 `static` 함수예요. 공통 헤더에는 추가하지 않아요. `read_sql_file()`과 `print_error()`의 구체적인 인자는 구현할 때 정해요.

| 함수 | 역할 | 실패 처리 |
| --- | --- | --- |
| `main()` | 인자 확인부터 공통 종료 경로까지 연결해요 | 처리, 정리, 출력 마무리 오류를 종료 코드에 반영해요 |
| `read_sql_file()` | SQL 버퍼와 실제 바이트 길이를 준비해요 | 열기, 읽기, 크기 계산, 크기 상한 초과, 할당, 입력 파일 닫기 실패를 확인하고 내부 자원을 정리해요 |
| `print_row()` | `Row`의 id, name, age를 출력해요 | 출력 함수가 실패하면 출력 오류를 반환해요 |
| `print_error()` | 실패 단계, 문장 번호, 상태에 맞는 원인을 출력해요 | 제공받지 않은 정확한 줄이나 열 위치를 추정하지 않아요 |

출력 콜백 선언은 공통 계약을 그대로 사용해요.

```c
static DbStatus print_row(const Row *row, void *user_data);
```

`user_data`에는 `stdout` 같은 `FILE *`를 넘겨요. 콜백은 행이나 문자열을 해제하지 않고, 호출이 끝난 뒤까지 포인터를 보관하지 않아요.

### 3.2 소유권과 수명

| 자원 | 준비와 소유 | 정리 |
| --- | --- | --- |
| SQL 입력 파일 | `read_sql_file()`이 열어요 | 같은 함수 안에서 닫아요 |
| SQL 버퍼 | 읽기 성공 후 `main`이 소유해요 | 공통 종료 경로에서 한 번 해제해요 |
| `Storage *` | `storage_open()` 성공 후 `main`이 관리해요 | `storage_close()`를 한 번 호출해요 |
| `Command command` | `main`의 지역 변수예요 | 다음 파싱에 재사용해요. 별도 해제는 없어요 |
| `char error[PARSE_ERROR_SIZE]` | `main`이 준비하는 128바이트 배열이에요 | 별도 해제는 없어요 |
| `ExecuteResult result` | 명령마다 결과를 받을 지역 변수예요 | 상태를 확인하고 유효한 결과만 읽어요 |

SQL 버퍼와 저장 포인터는 NULL로 초기화해요. 읽기 실패 시 버퍼 소유권을 넘기지 않아요. 빈 입력도 파서에 NULL을 넘기지 않도록 유효한 버퍼를 준비해요. 길이는 `strlen()`이 아니라 읽은 바이트 수예요. 중간 NUL 바이트를 파일 끝으로 오인하지 않아요.

크기 계산과 버퍼 확장에서는 `size_t` 오버플로를 확인해요. SQL 입력 상한은 16,777,216바이트(16MiB)예요. 초과하면 `input` 오류로 거절하고 저장소를 열지 않아요. 입력 파일을 닫는 과정에서 실패해도 읽기 성공으로 처리하지 않아요.

## 4. 처리 순서

| 순서 | 작업 | 성공 시 | 실패 시 |
| --- | --- | --- | --- |
| 1 | `argc` 확인 | SQL 파일을 읽어요 | 사용법을 stderr에 출력하고 종료해요. 저장소는 열지 않아요 |
| 2 | SQL 전체와 길이 준비(16MiB 상한 확인 포함) | 저장소를 열어요 | 원인을 출력하고 종료해요. 상한 초과면 저장소를 열지 않아요 |
| 3 | 고정 경로로 `storage_open()` 호출 | `cursor = 0`, 문장 번호 1로 시작해요 | SQL 버퍼를 해제하고 종료해요 |
| 4 | 이전 커서를 보관하고 `parse_next()` 호출 | `DB_OK`면 실행, `DB_END`면 반복을 끝내요 | 문장 번호와 파서 메시지를 출력하고 중단해요 |
| 5 | `execute(storage, &command, print_row, stdout, &result)` 호출 | 명령별 성공 결과를 출력해요 | 오류와 유효한 SELECT 부분 행 수를 알리고 중단해요 |
| 6 | 성공 결과 출력 확인 | 문장 번호를 늘리고 다음 문장으로 진행해요 | 이후 명령을 실행하지 않아요 |
| 7 | 열린 저장 상태 닫기, SQL 버퍼 해제 | 출력 마무리로 진행해요 | 종료 오류도 별도로 알리고 비정상 종료를 유지해요 |
| 8 | `fflush(stdout)` 확인 | 누적 실패 여부로 종료해요 | 출력 오류를 알리고 비정상 종료해요 |

호출 형태는 다음과 같아요. 이 코드는 반복문의 호출 관계를 보여 주는 예이며 오류 처리 전체를 대신하지 않아요.

```c
DbStatus status = parse_next(sql, length, &cursor, &command, error);
/* DB_OK와 커서 범위를 확인한 뒤 호출해요. */
status = execute(storage, &command, print_row, stdout, &result);
```

### 반복문에서 지킬 조건

1. `parse_next()`를 호출하기 전에 `cursor <= length`를 유지해요.
2. `DB_OK`인데 커서가 전진하지 않거나 길이를 넘으면 계약 위반으로 중단해요. 잘못된 커서로 다시 파서를 호출하지 않아요.
3. `DB_END`에서는 명령을 실행하거나 문장 번호를 늘리지 않아요. 파서가 건너뛴 빈 문장도 번호에 포함하지 않아요.
4. 문법 오류에서 파서가 커서를 다음 문장으로 옮겨도 CLI는 중단해요.
5. 명령, 오류 버퍼, 결과 공간을 재사용해요. `command_free()`는 없어요.

## 5. 출력과 오류

### 5.1 출력 대상과 유효한 결과

| 상황 | 대상 | 출력할 내용 |
| --- | --- | --- |
| SELECT 행 처리 | stdout | 헤더 없이 `id<TAB>name<TAB>age`를 한 줄씩 출력해요. name은 따옴표 없이 쓰고 `\`·탭·LF·CR은 각각 `\\`, `\t`, `\n`, `\r`로 표시해요 |
| INSERT 성공 | stdout | `INSERT OK id=N`이에요. 내부 레코드 위치는 출력하지 않아요 |
| SELECT 성공 | stdout | `SELECT OK rows=N`이에요. 빈 결과는 `SELECT OK rows=0`이에요 |
| 문법 오류 | stderr | `statement N: syntax: <파서의 영어 한 줄>`이에요. 파서 메시지는 줄바꿈 없이 NUL로 끝나요 |
| 실행 오류 | stderr | `statement N: <분류>: <원인>`인 영어 한 줄이에요. SELECT는 성공한 부분 행 수도 같은 줄에 알려요 |
| 입력, 종료, flush 오류 | stderr | `input: ...`, `close: ...`, `output: ...`처럼 단계와 원인을 쓰고, 명령 밖의 오류에 임의의 문장 번호를 붙이지 않아요 |

`<TAB>`은 실제 탭 문자를 뜻해요. INSERT 결과는 `DB_OK`일 때만 읽어요. SELECT 결과의 부분 행 수는 실패 시에도 읽을 수 있지만 전체 성공을 뜻하지 않아요. 실행 전 검증 실패라면 초기화된 0행이에요.

### 5.2 중단과 정리 규칙

- 전체 성공은 종료 코드 0, 하나라도 실패하면 1이에요.
- Linux에서는 출력이나 저장소 열기 전에 `SIGPIPE`를 `SIG_IGN`으로 설정해요. 설정 실패는 시작 오류로 처리하고 저장소를 열지 않아요. 닫힌 stdout 파이프의 쓰기·flush 실패(`EPIPE`)는 출력 오류로 처리해요. Windows MinGW-w64에는 `SIGPIPE`가 없어 이 단계가 없어요. 감지한 뒤에는 다음 명령을 실행하지 않고 공통 정리 경로에서 `storage_close()`와 SQL 버퍼 해제를 마쳐요.
- 행 출력 실패는 `print_row()`에서 출력 오류로 반환해요. 저장 스캔과 실행기를 거쳐 CLI로 전달되면 다음 명령을 실행하지 않아요.
- 성공 결과 출력 실패도 중단 원인이에요. INSERT 성공 뒤 출력만 실패했다면 저장은 이미 끝났을 수 있어요. 다시 INSERT하라고 안내하지 않아요.
- 콜백 성공은 출력 함수가 성공했다는 뜻이에요. 버퍼의 데이터가 최종 목적지까지 전달됐다는 보장은 아니므로 마지막 `fflush(stdout)`도 확인해요.
- 최초 오류를 유지하고 `storage_close()`나 flush의 추가 오류도 알려요. stderr 출력 자체가 실패하더라도 비정상 종료 코드는 유지해요.
- `storage_close()`는 성공과 실패 모두 상태를 해제해요. 호출 직후 포인터를 NULL로 바꾸고 다시 닫지 않아요.
- 기록 결과 불확실 오류는 그대로 알리고 재시도하지 않아요. 실패한 INSERT가 파일을 전혀 바꾸지 않았다고 단정하지 않아요.

## 6. 테스트

[테스트 세부 설계](test.md)의 SQL 파일 테스트로 삽입, 조회, WHERE, 중간 오류 후 중단과 정상 재시작을 확인해요. 임시 디렉터리에서 실행하고 stdout, stderr, 종료 코드와 재조회 결과를 확인해요.

인자 누락, 추가 인자, 없는 SQL 파일 경로, 빈 SQL 입력과 입력 크기 경계(16,777,216바이트와 1바이트 초과)도 확인해요. 출력, flush, close 실패 주입은 기본 기능을 연결한 뒤 보강해요.

## 7. 정하지 않은 것

| 항목 | 필요한 결정 | 같이 정할 사람 |
| --- | --- | --- |
| 결과 표현 | `ExecuteResult`의 실제 필드명과 구분 방식이에요 | 전원 |
| 오류 상태 | 인자, 출력, 모듈 계약 위반 등을 나타낼 실제 상태 값과 enum 수치예요 | 전원 |
| 오류 문구 | 오류 분류 이름과 각 분류에 붙일 영어 원인 문장이에요 | 최무헌 |

파서의 영어 한 줄 오류 메시지와 CLI의 영어 한 줄 오류 형식은 확정됐어요. 분류 이름과 상태별 원인 문구는 공통 상태 값에 맞춰 구현 전에 정해요. 저장 레코드 위치는 바이트 오프셋으로도, `INSERT OK` 출력으로도 드러내지 않아요.

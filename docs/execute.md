# 실행기 세부 설계 (`execute.c`, 최무헌)

> **기준 문서:** [모듈 구성과 호출 계약](architecture.md), [파서 세부 설계](parser.md).

## 1. 맡는 것과 맡지 않는 것

| 맡는 것 | 맡지 않는 것 (담당) |
| --- | --- |
| 명령 종류, 테이블, 값 개수와 타입 검사 | SQL 파일 읽기, 화면 출력, 저장소 열기와 닫기 (`main.c`) |
| 스키마의 문자열 길이와 정수 범위 검사 | SQL 문장과 토큰 해석 (`parser.c`) |
| INSERT 또는 SELECT 저장 함수 호출 | 자동 ID 발급, 직렬화, 파일 복원 (`storage.c`) |
| WHERE 검증과 일치 행 전달, 부분 행 수 집계 | 인덱스, 실행 계획 계층, 명령 등록 체계 |

검증에 실패한 명령으로 저장 함수를 호출하지 않는 것이 핵심이에요. 공개 함수 `execute()`와 필요한 내부 필터 함수만 두고, 별도 실행기 계층은 만들지 않아요.

## 2. 공개 함수와 명령 표현

```c
DbStatus execute(Storage *storage, const Command *command,
                 RowHandler on_row, void *user_data,
                 ExecuteResult *out_result);
```

| 인자 | 방향 | 내용 |
| --- | --- | --- |
| `storage` | 입력 | 이미 열린 저장 상태예요 |
| `command` | 입력 | 파서가 채운 고정 크기 명령이에요. 실행 중 변경하지 않아요 |
| `on_row` | 입력 | SELECT의 일치 행을 처리할 외부 콜백이에요 |
| `user_data` | 입력 | 외부 콜백에 그대로 전달할 상태예요 |
| `out_result` | 출력 | INSERT 성공 결과 또는 SELECT의 성공 처리 행 수예요 |

`CommandType`, `ValueType`, `Value`, `Command`는 [파서 설계 3.1절](parser.md#31-dbmsh에-들어갈-파서-쪽-정의)의 정의를 공통 헤더에서 사용해요.

- INSERT는 `values[0]`에 문자열 name, `values[1]`에 정수 age를 담아요. id는 입력받지 않아요.
- SELECT는 `has_where`, `where_column`, `where_value`로 단일 동등 조건을 표현해요.
- 파서 한도는 식별자 31바이트, 문자열 255바이트, 값 16개예요. 문자열 한도는 끝의 NUL을 제외해요.
- INSERT 열 목록, SELECT 출력 열 지정, 복합 조건, 정렬 같은 미지원 문법은 파서가 거절해요. 실행기가 이를 조용히 무시하고 다른 의미로 실행하지 않아요.

## 3. 공통 검증

| 검사 | 통과 조건 | 실패 시 |
| --- | --- | --- |
| 출력 공간 | `out_result != NULL` | 인자 오류를 반환해요. 결과를 쓰지 않아요 |
| 결과 초기화 | 유효한 결과 공간을 먼저 초기화해요 | 검증 실패의 SELECT 행 수도 0으로 유지해요 |
| 필수 입력 | `storage`, `command`가 NULL이 아니에요 | 인자 오류를 반환해요 |
| 명령 종류 | `CMD_INSERT` 또는 `CMD_SELECT`예요 | 미지원 명령 오류를 반환해요 |
| 테이블 | 고정 배열 안에 NUL이 있고 users를 가리켜요 | 스키마 오류를 반환해요 |

모든 검증 실패에서는 저장 함수와 외부 콜백을 호출하지 않아요. 실제 오류 상수와 결과 필드는 공통 헤더에서 맞춰요.

키워드, 테이블명과 조건 열은 대소문자를 구분하지 않아요. 파서는 식별자의 원문을 보존하고, 실행기는 테이블명과 조건 열을 `strcmp` 대신 `strcasecmp`로 비교해요. `users`, `USERS`, `Users`는 같은 테이블이고, `age`와 `Age`는 같은 열이에요.

오류에 식별자를 표시할 때는 `table 'USERS' does not exist`처럼 사용자가 쓴 원문을 그대로 써요. 비교를 위해 명령 안의 이름을 소문자로 덮어쓰지 않아요. 저장 경로는 `users.sans`로 고정이므로 식별자의 대소문자는 파일 이름에 영향을 주지 않아요.

문자열은 고정 배열 안에 NUL이 있는지 먼저 확인한 뒤 비교해요. 테스트에서 직접 만든 비정상 명령도 배열 밖으로 읽지 않아요. `user_data`는 콜백이 해석하므로 실행기가 검사하거나 NULL이라는 이유만으로 거절하지 않아요.

## 4. INSERT 처리

| 순서 | 검증 또는 작업 | 실패 시 |
| --- | --- | --- |
| 1 | `value_count == 2`인지 확인해요 | 값 배열을 읽지 않고 스키마 오류를 반환해요 |
| 2 | 첫 값은 `VALUE_STRING`, 둘째 값은 `VALUE_INT`인지 확인해요 | 타입 오류를 반환해요. 자동 변환하지 않아요 |
| 3 | name의 NUL 종료, 64바이트 이하, 빈 이름 허용을 확인해요 | 스키마 또는 범위 오류를 반환해요 |
| 4 | age가 `int32_t` 범위인지 확인해요 | 범위 오류를 반환해요 |
| 5 | `storage_insert(storage, name, age, &insert_result)`를 한 번 호출해요 | 저장 오류를 그대로 반환해요 |
| 6 | 성공한 ID와 레코드 위치를 실행 결과로 복사해요 | 성공일 때만 결과를 유효하게 취급해요 |

INSERT는 `on_row == NULL`이어도 허용하고 콜백을 호출하지 않아요. 문자열 `'20'`을 정수 20으로 바꾸거나 정수를 name 문자열로 바꾸지 않아요.

ID를 미리 계산하거나 검증용 INSERT를 하지 않아요. ID 발급, 중복 방지, 파일 탐색과 바이너리 쓰기는 저장 모듈의 책임이에요. 기록 결과 불확실 오류도 다른 오류로 바꾸거나 자동 재시도하지 않아요.

## 5. SELECT와 WHERE 처리

### 5.1 조건 검증

SELECT에는 `on_row`가 필요해요. NULL이면 저장 호출 없이 인자 오류를 반환해요.

| 조건 | 검증 |
| --- | --- |
| WHERE 없음 | 전체 스캔 경로를 사용해요 |
| `id = 정수` | `int64_t` 자료형과 1 이상 범위를 확인해요 |
| `name = 문자열` | 고정 배열의 NUL 종료, 64바이트 이하, 빈 문자열 허용을 확인해요 |
| `age = 정수` | `int32_t` 자료형과 범위를 확인해요 |
| 없는 열, 잘못된 타입이나 범위 | 저장 호출 없이 오류를 반환해요 |

`where_column`도 고정 배열 안에서 NUL 종료를 확인해요. name의 빈 문자열 허용과 64바이트 한도는 INSERT 검증과 같아요.

### 5.2 WHERE 없는 경로

`storage_scan(storage, on_row, user_data, &count)`를 한 번 호출해요. 원래 함수 포인터와 상태 주소를 그대로 전달해요. 반환 상태와 성공 콜백 수를 실행 결과에 옮겨요. 빈 테이블은 `DB_OK`와 0행이에요.

### 5.3 WHERE 있는 경로

파일은 한 번 선형 탐색해요. 저장 모듈에 조건 해석을 맡기지 않고 실행기 내부 콜백에서 행을 걸러요.

내부 상태에는 현재 조건을 담은 읽기 전용 명령 포인터, 원래 `on_row`, 원래 `user_data`, 성공한 일치 행 수를 둬요. 요청마다 지역 변수로 준비하고 전역 상태나 별도 할당은 사용하지 않아요.

```text
execute
  -> storage_scan(내부 필터 콜백, 요청별 필터 상태, 저장 스캔 개수)
       -> 불일치: 외부 콜백 없이 DB_OK
       -> 일치: 원래 on_row(row, 원래 user_data)
            -> DB_OK: 성공한 일치 행 수를 1 늘림
            -> 오류: 개수를 늘리지 않고 같은 오류 반환
```

숫자는 정수 값으로 비교하고 문자열은 값의 동등성을 비교해요. 문자열 조건을 부분 일치로 처리하지 않아요. 외부 콜백은 원래 `user_data`를 받아야 하며 내부 필터 상태 주소를 받으면 안 돼요.

`storage_scan()`의 개수에는 불일치 행도 포함될 수 있어요. 따라서 WHERE 조회 결과에는 그 개수를 복사하지 않고 **외부 콜백이 성공한 일치 행 수**를 사용해요. 성공과 실패 모두 이 개수를 실행 결과에 기록하고, 저장 또는 외부 콜백의 오류는 그대로 반환해요.

예를 들어 불일치 1행 뒤 일치 2행이 있고 두 번째 일치 행에서 출력이 실패하면, 외부 콜백은 2회 호출되고 결과 개수는 1이에요. 이후 행은 처리하지 않아요.

## 6. 반환값과 수명

| 상황 | 반환과 결과 |
| --- | --- |
| 검증 실패 | 해당 오류를 반환해요. 저장 호출은 없고 유효한 결과 공간은 초기화된 상태예요 |
| INSERT 성공 | `DB_OK`, 저장한 ID와 레코드 위치예요 |
| INSERT 실패 | 저장 오류를 그대로 반환해요. INSERT 결과를 사용하지 않아요 |
| SELECT 성공 | `DB_OK`, 외부 콜백이 성공한 행 수예요 |
| SELECT 중간 실패 | 원래 오류와 성공 처리한 일부 일치 행 수예요 |

- `DB_END`는 파서 전용이에요. 조회 결과가 0행이어도 `DB_OK`예요.
- 명령, 문자열, 저장 상태, 외부 콜백 상태는 빌려 사용해요. 변경하거나 해제하거나 함수 종료 뒤까지 보관하지 않아요.
- 저장 콜백과 필터는 `storage_scan()` 호출 중 동기적으로 실행돼요. 지역 필터 상태는 스캔이 끝날 때까지 유효해요.
- 행과 행 내부 문자열은 콜백 호출 중에만 유효해요. 결과 배열을 만들거나 포인터를 남겨 두지 않아요.
- 저장소 종료와 출력 오류의 최종 종료 코드 반영은 [CLI 설계](main.md)의 책임이에요.

## 7. 테스트

[테스트 세부 설계](test.md)의 E01~E03을 저장 함수 대역으로 확인해요.

- 정상 INSERT의 값과 성공 결과가 전달되는지 확인해요.
- 잘못된 테이블, 값과 조건을 저장 호출 없이 거절하는지 확인해요.
- WHERE의 일치 행만 전달하고 결과 개수를 정확히 세는지 확인해요.

저장과 외부 콜백의 실패 주입은 기본 기능을 연결한 뒤 보강해요.

## 8. 정하지 않은 것

| 항목 | 필요한 결정 | 같이 정할 사람 |
| --- | --- | --- |
| 공통 타입 | `ExecuteResult`의 실제 필드와 상태 값이에요 | 전원 |

`Row`, `InsertResult`, name 64바이트·빈 문자열 허용, age `int32_t`, id 1 이상 `int64_t`는 PR #1에서 확정됐어요. 파서의 255바이트 문자열 한도나 `int64_t` 표현 범위를 저장 스키마의 허용 범위로 쓰지 않고, 검증과 경계 테스트에 확정된 스키마 값을 사용해요.
